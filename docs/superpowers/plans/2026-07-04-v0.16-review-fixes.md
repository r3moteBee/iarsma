### Task 2: JMAP-valid keyword inverses; no undo for bulk keyword patches

`buildInverse` negates keyword patches blindly: `!null === true` and `!true === false` — `false` is an RFC 8621-invalid keyword patch value, and a uniform inverse over 2+ emails with mixed prior flag states corrupts them (undoing a bulk Unflag of 10 threads flags all 10). Fix: keyword inverses use the `true`→`null`, `null`→`true` dialect, and keyword patches spanning more than one email register no undo at all.

**Files:**
- Modify: `shell/src/runtime/undo-registry.ts:113-135` (`buildInverse` mail.modify branch) and `:182-186` (`flipBooleans` — add a `flipKeywords` sibling)
- Test: `shell/src/runtime/__tests__/undo-registry.test.ts:108-135` (two existing tests change expectations; new tests added)

**Interfaces:**
- Consumes: nothing new.
- Produces: `buildInverse('mail.modify', …)` now returns `null` when `patch.keywords !== undefined && emailIds.length > 1`; keyword inverse values are `boolean | null`. `loggingInvoker` already handles a `null` return (no registration, no hook).

Below `flipBooleans` (line ~182), add:

```ts
function flipKeywords(
  m: Readonly<Record<string, boolean | null>>,
): Record<string, boolean | null> {
  // Keyword patch dialect (RFC 8621): true adds, null removes; false
  // is not a valid patch value. Inverse of add is remove and vice versa.
  const out: Record<string, boolean | null> = {};
  for (const [k, v] of Object.entries(m)) out[k] = v === true ? null : true;
  return out;
}
```
